BEFORE (v1.0): Single-Tier Keyword Classifier
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

User Input
    ↓
IntentClassifier (Keyword-based)
    ├─ Match keywords
    ├─ Extract simple parameters
    └─ Return Intent
    ↓
Execute Tasks

Limitations:
  ✗ Cannot understand context nuance
  ✗ Struggles with ambiguous queries
  ✗ Fixed parameter extraction
  ✗ Confidence is implicit


AFTER (v2.0): Two-Tier Intelligent Classification
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

User Input
    ↓
CompositeIntentClassifier
    ├─ Tier 1: LLMIntentClassifier (Semantic)
    │  ├─ Semantic understanding
    │  ├─ Structured entity extraction
    │  ├─ Confidence scoring
    │  └─ Fast failure with fallback
    │
    ├─ Tier 2: KeywordBasedIntentClassifier (Fallback)
    │  ├─ Keyword pattern matching
    │  ├─ Reliable extraction
    │  ├─ No API dependencies
    │  └─ Always available
    │
    └─ Intelligence: Use LLM if confident, else fallback
    ↓
Enhanced Intent (with entities, reasoning, source)
    ↓
Execute Tasks (with LLM-extracted parameters)

Advantages:
  ✓ Semantic understanding (context-aware)
  ✓ Handles ambiguous, complex queries
  ✓ Structured entity extraction (JSON)
  ✓ Explicit confidence scoring
  ✓ Automatic intelligent fallback
  ✓ Backward compatible (works without LLM)

┃ 3. CLASSIFICATION FLOW (DETAILED)                                            ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

Example: "Search for Docker containerization and check if port 8080 is up"

┌─────────────────────────────────────────────────────────────────┐
│ STEP 1: INPUT → COMPOSITE CLASSIFIER                            │
└─────────────────────────────────────────────────────────────────┘

  User Input: "Search for Docker containerization and check if port 8080 is up"
       ↓
  CompositeIntentClassifier.classify()


┌─────────────────────────────────────────────────────────────────┐
│ STEP 2: TIER 1 - LLM SEMANTIC CLASSIFICATION                   │
└─────────────────────────────────────────────────────────────────┘

  LLMIntentClassifier.classify()
       ↓
  Build semantic prompt with:
    - Supported task types with descriptions
    - Entity extraction requirements
    - User's natural language input
       ↓
  LLM API Call (Claude, GPT, etc.)
       ↓
  Parse JSON Response:
  {
    "task_type": "combined",
    "primary_query": "Docker containerization",
    "confidence": 0.92,
    "entities": [
      {
        "entity_type": "search_query",
        "value": "Docker containerization",
        "confidence": 0.95
      },
      {
        "entity_type": "port_number",
        "value": 8080,
        "confidence": 0.98
      }
    ],
    "parameters": {
      "search_query": "Docker containerization",
      "port": 8080,
      "max_results": 5
    },
    "reasoning": "User asked for both search and port check"
  }
       ↓
  Create Intent object with:
    - task_type: COMBINED
    - primary_query: "Docker containerization"
    - entities: [search_query(0.95), port_number(0.98)]
    - parameters: {search_query, port, max_results}
    - confidence: 0.92
    - classifier_used: "llm"
    - reasoning: "..."


┌─────────────────────────────────────────────────────────────────┐
│ STEP 3: CONFIDENCE CHECK                                         │
└─────────────────────────────────────────────────────────────────┘

  Is LLM confidence (0.92) >= threshold (0.70)?
       ↓
  YES → Use LLM result
  (Skip Tier 2)


┌─────────────────────────────────────────────────────────────────┐
│ STEP 4: STRUCTURED INTENT RETURNED                              │
└─────────────────────────────────────────────────────────────────┘

  Intent(
    task_type=COMBINED,
    primary_query="Docker containerization",
    secondary_queries=[],
    parameters={
      "search_query": "Docker containerization",
      "port": 8080,
      "max_results": 5
    },
    entities=[
      ExtractedEntity("search_query", "Docker containerization", 0.95),
      ExtractedEntity("port_number", 8080, 0.98)
    ],
    confidence=0.92,
    classifier_used="llm",
    reasoning="User asked for both search and port check"
  )


┌─────────────────────────────────────────────────────────────────┐
│ STEP 5: TASK EXECUTION WITH LLM DATA                           │
└─────────────────────────────────────────────────────────────────┘

  For WEB_SEARCH:
    - query = "Docker containerization" (from entity extraction)
    - max_results = 5 (from parameters)
    - Returns 5 search results
  
  For PORT_CHECK:
    - port = 8080 (from entity extraction)
    - Returns port status
  
  Both use LLM-extracted, structured parameters


FALLBACK SCENARIO (If LLM confidence < threshold):

  LLM confidence 0.55 < threshold 0.70?
       ↓
  Fall back to Tier 2 (KeywordBasedIntentClassifier)
       ↓
  Keyword matching:
    - "Search for" → WEB_SEARCH
    - "port" → PORT_CHECK
    - Both present → COMBINED
       ↓
  Return Intent (classifier_used="keyword")


FAILURE SCENARIO (If LLM API fails):

  LLMIntentClassifier.classify() throws exception
       ↓
  Log error
       ↓
  Fall back to Tier 2 (KeywordBasedIntentClassifier)
       ↓
  Return valid Intent using keyword classification
       ↓
  User never sees an error (graceful degradation)

┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

INHERITANCE:

  IntentClassifierBase (ABC)
      ├─ KeywordBasedIntentClassifier
      ├─ LLMIntentClassifier
      └─ CompositeIntentClassifier

DESIGN PATTERNS:

  Strategy Pattern (per classifier type)
    - Each classifier implements same interface
    - Can swap implementations at runtime

  Decorator Pattern (composite wrapper)
    - CompositeIntentClassifier wraps both tiers
    - Adds intelligent routing logic

  Fallback Pattern (graceful degradation)
    - Tier 1 fails → Tier 2 activates
    - Always returns valid Intent

  Cache Pattern (performance optimization)
    - LLM results cached per unique input
    - Reduces redundant LLM calls

  Factory Pattern (HermesAgent creation)
    - create_hermes_agent_with_modules()
    - Handles LLM client injection
